# Official WhatsApp setup

Harbor’s WhatsApp adapter talks only to:

- `https://graph.facebook.com` for WhatsApp Cloud API
- `https://verify.twilio.com` when Twilio Verify is the OTP provider

It does not implement WhatsApp Web, multi-device pairing, or QR session capture.

## Cloud API connection

1. In Meta Business Manager, create an app and add the WhatsApp product.
2. Add a phone number and copy its Phone number ID.
3. Create a system user with WhatsApp permissions and generate a permanent token. Store it as `WHATSAPP_ACCESS_TOKEN`.
4. Set `WHATSAPP_PHONE_NUMBER_ID` and, if you have it, `WHATSAPP_BUSINESS_ACCOUNT_ID`.
5. Set `WHATSAPP_PROVIDER=cloud`.
6. Deploy, open `/admin`, and choose **+ Add session**.
7. The modal states that this provider has no QR login. **Verify connection** calls Graph API `GET /{phone-number-id}` and stores only non-sensitive metadata: display name, phone number, status, quality rating, and ids.

Status mapping:

- Meta `CONNECTED` → green Connected
- `PENDING` or `MIGRATED` → yellow Connecting
- OAuth errors such as code 190 → Session expired
- Missing credentials → Disconnected
- Local Disconnect keeps the row but stops treating it as active
- Delete removes Harbor’s row only. Rotate the token in Meta if it may have been exposed.

Reconnect repeats the live Graph API check. It does not open a WhatsApp Web socket.

## OTP template

Create an approved Authentication template in WhatsApp Manager. Set:

```text
OTP_PROVIDER=whatsapp_cloud
WHATSAPP_OTP_TEMPLATE=your_template_name
WHATSAPP_OTP_TEMPLATE_LANG=en_US
```

Harbor sends the official template message with the code in the body. Authentication templates that use a URL/copy button also receive the code as the button parameter. If your template has no button, set `WHATSAPP_OTP_INCLUDE_BUTTON=false`.

The code is generated by Harbor, hashed with `OTP_PEPPER`, and never written to the user table. Twilio Verify is the exception: Twilio generates and checks the code, and Harbor stores `external` instead of a hash.

## Webhook

In the Meta app, set the callback URL to:

```text
https://your-app.vercel.app/api/webhooks/whatsapp
```

Use `WHATSAPP_WEBHOOK_VERIFY_TOKEN` as the verify token and `WHATSAPP_APP_SECRET` so Harbor can check `X-Hub-Signature-256`. The handler acknowledges events and updates `lastCheckedAt`. It does not import WhatsApp chat text into Harbor conversations.

## Why there is no login QR

The official Cloud API authenticates the business with a token, Embedded Signup, or a business-solution provider such as Twilio. Those flows are not the QR code used by WhatsApp Web clients. Building that QR flow would violate the project rule and WhatsApp’s terms, so it is intentionally absent.
